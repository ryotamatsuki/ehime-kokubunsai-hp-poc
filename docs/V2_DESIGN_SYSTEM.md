# v2の共通設計 — 愛媛を、ひらく。

対象：2.0.0-alpha.6。状態：cultural-editorial-review。
本文を保ったまま、祝祭の入口、土地の記録、利用者のことば、実務案内を異なる構成でつなぐ。
完成判定は `V2_QUALITY_GATE.md` に従う。

## 文字から画面の階層をつくる

日本語の主見出しはZen Maru Gothic Medium 500、本文はZen Kaku Gothic New Regular 400を使う。
英字と数字はManropeの可変書体200–800を使う。
主見出しの丸みを、人の集まりと文化をひらく入口に用い、本文・操作・実務ページの小見出しは落ち着いた角ゴシックにする。
太字を全体へ敷く組み方と、日本語を強く詰める見出しを改めた。
大きさ、余白、藍の色、境界で重要度を示す。

| 用途 | 書体と組み方 |
| --- | --- |
| トップ主見出し | Zen Maru Gothic Medium 500、1440px幅94px、390px幅64px、320px幅60px。二行の「愛媛を、／ひらく。」 |
| ページの主見出しと編集的な章題 | 同500、字間0.01em、基本行間1.35–1.5 |
| 本文 | Zen Kaku Gothic New 400、PC20px、小画面18px。文化本文は最大720px |
| 実務の小見出し、催し名、操作 | 本文書体。CSSの500要求は収録400へ対応し、英数字はManrope500。サイズ・色・余白で階層を補う |
| 日時・料金・主要な補足 | 16–20px。会期の数字は32–36px以上 |
| 読むための操作・入力 | 原則18px以上、操作高さ48px、最低44px |
| 写真の著作情報と小さな索引 | 13–16px。本文や開催状態を代替しない |

CSSの別名はEhime Festival Display、Ehime Sans、Ehime Latin。
元書体の固定コミット、SHA-256、OFL、使用文字、容量は `design-lab/assets/manifest.json` に記録する。
表示書体は大見出しに必要な文字を中心に、本文は全掲載文字を収録する。
使用頻度の高い文字と64文字ずつの追加範囲に分け、`unicode-range` と `font-display:swap` で必要な書体を選ぶ。
各分割ファイルの内部PostScript名を固有にし、複数ファイルを同じ文書へ埋め込んだ際の字形取り違えを防ぐ。
追加文字のある改訂は書体も再生成し、収録範囲を検査する。

## 主景を早く見せ、土地の文化へすぐつなぐ

PCは5:7の非対称グリッドで、見出しと主画像を同じ開始位置から見せる。
小画面では索引、主見出し、主画像、説明、会期、操作の順へ組み替える。
トップの文化紹介は主景の直後に置き、6件の催し一覧を通過する前に読めるようにした。
催し一覧はPCで小さな画像を添えた3列2段、小画面は一列とする。
全6件の名称・日程・掲載状態・個別画像を表示し、料金・支援・申込の情報は検索と詳細へつなぐ。

土地の文化は、東予・中予・南予の実写記録と一次出典を軸にする。
四つのジャンルの入口は短い並びへまとめ、写真・本文・催しへの導線を各章で異なる構成にする。
「愛媛を、ひらく。」はPoCの提案コピーであり、公式ロゴや正式キャッチフレーズとして扱わない。

## 下層ページの読む目的を分ける

元本文は `scripts/v2_preserve_content.py` により全て移行する。
元の説明順を固定せず、具体的な内容や記入欄を先へ、目的・出典・関連案内は必要に応じて開ける補足へ再編集する。
開閉欄にも本文を残し、目次とURLのアンカー移動では該当欄を開く。

| ページ型 | 画面の特徴 |
| --- | --- |
| 大会紹介・記録・広報 | 写真と読み物を先に置く編集的な構成 |
| 募集 | 条件・参加の入口を強調し、説明と手順を区切る |
| 協賛 | 協力の目的、具体例、関心表明の欄を主役にする |
| 観光・アクセス | 経路や場所の視覚情報、行程、詳しい案内の順 |
| 委員会・資料・方針 | 内容の索引と文書の読みやすさを優先する |
| お知らせ・報道 | 掲載内容と更新を見分ける記事の構成 |
| 問い合わせ | 記入欄・窓口の位置を先に確保する |
| 支援・共通案内 | 確認する項目と相談先を読みやすい順に置く |
| 催しの案内 | 日付・条件・個別の具体例を先に置く |

ヘッダー、出典表示、操作の文法は共通にする。
元の全114ページの情報は保持し、元トップの本文は `festival-guide.html` へ配置する。

## 内容に結び付く操作

文化の記録はアンカーを基本にし、JavaScriptがあればキーボードで選べるタブへ拡張する。
写真と背景から気づいたことを文化帖に残し、写真の情報と一次出典を添えたTXTとして持ちかえる。
文学の章では、かなの五・七・五を確認し、作ったことばを縦書きSVGとして保存する。
工芸の章の任意の絵付け、催し検索、保存・削除、URLによる検索条件の復元も維持する。

文化帖の自分のことばと俳句の下書きはブラウザー内に保存し、催しの共有URLに含めない。
未定義のID、保存失敗、空の状態、削除後のフォーカスを扱う。
自由入力はHTMLに変換せず、SVGへ出力するときはXMLをエスケープする。
オフライン確認画面へ渡す文字もスクリプトの構造を壊さない形へ符号化する。

高コントラスト、フォーカス、印刷時の状態も定義する。

## 素材と配信

全6催しのAI画像と文化祭全体の主画像は引き続き同梱する。
この版では実写記録4点と配信用WebP12点を追加する。
生成イメージと実写記録の役割、撮影場所・時期・著作条件を区別して示す。
`V2_ART_DIRECTION.md` と `V2_CULTURAL_RESEARCH.md` を参照する。

確認用129ページ、通常128ルートを生成する。
通常配信はレスポンシブ画像と遅延読込を用い、全ページ同梱のreview.htmlの容量とは分けて評価する。
Unicode範囲に基づく書体の容量概算を実測の表示速度として扱わない。
GitHub Pages通常配信のChromeで主要15ページ×320/390/1440pxと主要操作を確認した。
本文・操作の横はみ出し、読み込み済み画像のエラーは全45表示で0。
200%拡大、支援技術、実機、十分なCore Web Vitals測定の最終ゲートは保留である。
